# When something goes wrong

Every message a script prints on failure is in a table on this page. Look at the first line of what you see. Find that line in the first column. Then read across: what it means, and how to fix it.

For example, you run `uv run fernhill demo --lease L999` and see `There is no lease L999. Leases run from L001 to L130.` Look for `There is no lease ...` in the first table. The fix says to use an id from L001 to L130.

## Setup and the world

| What you see                                                     | What it means                                                      | Fix                                                                                                                                               |
| ---------------------------------------------------------------- | ------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| `bun: command not found`                                         | Bun is not installed, or your terminal does not know about it yet. | Install it from bun.sh. Then close the terminal and open a new one, so it finds `bun`.                                                            |
| `uv: command not found`                                          | uv is not installed, or your terminal does not know about it yet.  | Install it from docs.astral.sh/uv. Then close the terminal and open a new one, so it finds `uv`.                                                  |
| `No interpreter found for Python >=3.12`                         | uv cannot find Python 3.12 or newer on your machine.               | Let uv install one: run `uv python install 3.13`, then run `uv sync` again.                                                                       |
| `There is no step called "..."`                                  | `bun run verify` does not know that step name. It is often a typo. | Copy a name from the list it prints. For example, `bun run verify sample-traces` fails; `bun run verify sample-the-traces` works.                 |
| `There is no part called "..."`                                  | `bun run verify part` does not know that part name.                | Copy a name from the list it prints. For example, use `bun run verify part find-the-failures`, without the `01-` at the front.                    |
| `ERROR the check for ... could not load`                         | The check itself is broken. Your work is not the problem.          | Open an issue on the repo and paste the full output.                                                                                              |
| `There is no step called ... Try: uv run review mark-the-traces` | The review app only opens for a step that has traces to review.    | Use one of the two review steps: `uv run review mark-the-traces` or `uv run review note-the-failures`.                                            |
| `Address already in use`                                         | Another review app is already running on that port.                | Go to the terminal that runs it and press Ctrl+C. Or start a second one on another port, for example `uv run review mark-the-traces --port 8766`. |
| `There is no lease ...`                                          | `uv run fernhill demo --lease` got an id that does not exist.      | Use an id from L001 to L130. For example, `uv run fernhill demo --lease L008` shows the lease whose amendment the abstractor misses.              |
| `Use: uv run world [status\|reset\|tour\|lease <id>\|generate]`  | `uv run world` got a word it does not know.                        | Use one of the words in the brackets. For example, `uv run world tour` or `uv run world lease L008`.                                              |
| `Use: uv run fernhill demo \| report \| gate --release <name>`   | `uv run fernhill` got a word it does not know.                     | Use one of the words it lists. For example, `uv run fernhill report`.                                                                             |
| `could not score the release: no release called`                 | `uv run fernhill gate --release` got a name that is not a release. | Use a file name from `world/data/releases` without `.json`: `live`, `cheaper-model`, `shorter-prompt` or `clause-ids-in-answer`.                  |
| `FileNotFoundError: ... world/data/...`                          | The world's data files are missing or were moved.                  | Get them back from git with `git checkout -- world/data`, then run `uv run world reset`.                                                          |
| `sqlite3.OperationalError: no such table`                        | Your system of record (the database) comes from an older repo.     | Run `uv run world reset`. It builds the database again from `world/data`.                                                                         |

## Models and keys

| What you see                                                    | What it means                                                                                                    | Fix                                                                                                                                                        |
| --------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `No recorded reply for this prompt`                             | Replay mode answers only the prompts the finished system sends. You sent a new prompt, so it has no reply saved. | To try your own prompt, set `LLM_PROVIDER` and one key in `.env` to run it live. Or go back to the finished system's prompt.                               |
| `LLM_PROVIDER=... needs ..._API_KEY in .env`                    | You chose a provider, but its key is empty.                                                                      | Copy `.env.example` to `.env` and fill in that one key. For example, `LLM_PROVIDER=anthropic` needs `ANTHROPIC_API_KEY`.                                   |
| `LLM_PROVIDER=... is not known`                                 | The provider name is misspelled.                                                                                 | Use one of `replay`, `anthropic`, `openrouter`, `openai` or `ollama`. For example, `LLM_PROVIDER=foo` prints this message; `LLM_PROVIDER=openai` does not. |
| `LLM_PROVIDER=ollama needs OLLAMA_MODEL in .env`                | Ollama runs a model on your own machine, and you have not said which one.                                        | Set `OLLAMA_MODEL` in `.env` to a model you have already pulled with Ollama.                                                                               |
| `role(s) failed` from `uv run models`                           | A live call failed. The usual reasons are a wrong key, no credit left, or no network.                            | Read the `FAIL` lines above it. For example, `fast   FAIL  LLM_PROVIDER=anthropic needs ANTHROPIC_API_KEY in .env` means the key is empty.                 |
| `AuthenticationError`                                           | The provider did not accept your key.                                                                            | Make a new key on the provider's site. Paste it into `.env` with no spaces and no quotes around it.                                                        |
| `TPR + TNR must be above 1; the judge is no better than chance` | Your judge agrees with Dana no more often than a coin toss would, so its errors cannot be corrected.             | Improve the judge first. For example, with TPR 0.60 and TNR 0.40 the sum is 1.00, which is not enough. The finished judge has TPR 0.92 and TNR 0.88.       |

## Check messages

`bun run verify <step-name>` prints one line per rule. A `FAIL` line names a rule your work does not meet yet. Under it, a `Try next:` line says what to do.

For example, on a new copy of the repo, `bun run verify meet-fernhill` prints this:

```text
  FAIL  report.txt exists in this folder
        Try next: from the repo root run uv run fernhill report --out 00-orientation/01-meet-fernhill/problem/report.txt
```

In the table, the name in brackets is the step the rule belongs to. The Fix column says the same thing as `Try next:`, with an example.

| What you see                                                                                                              | What it means                                                                                                           | Fix                                                                                                                                                                                    |
| ------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `FAIL  rates.json has n, top_mode and modes` (count-the-failures)                                                         | `rates.json` is missing, or one of its three keys is missing or has the wrong type.                                     | Keep the shape of the starter `rates.json` and fill it in, or write it from `count.py`. For example, `"n": 40` is a number and `"top_mode": "amended-rent-missed"` is text.            |
| `FAIL  n is the number of reviewed traces in labels.csv` (count-the-failures)                                             | `n` must count every trace you reviewed, passed and failed.                                                             | Count the rows of `labels.csv`, not only the failed ones. For example, the sample solution has 40 rows, so `"n": 40`.                                                                  |
| `FAIL  every mode has a count and a rate that match labels.csv` (count-the-failures)                                      | A count or a rate in `rates.json` differs from what `labels.csv` says.                                                  | Compute the numbers from `labels.csv` with code: count = the 1s in the column, rate = count / n. For example, 4 ones out of 40 rows gives `"count": 4, "rate": 0.1`.                   |
| `FAIL  top_mode has the highest count` (count-the-failures)                                                               | `top_mode` names a mode that does not have the most 1s.                                                                 | Set `top_mode` to the mode with the most 1s. If two modes tie, either one is right.                                                                                                    |
| `FAIL  every mode has a decision: fix the prompt, code check, judge or monitor` (count-the-failures)                      | A mode has no decision, or the decision is spelled another way.                                                         | Pick one of the four decisions for each mode, spelled exactly as shown. For example, `"decision": "code check"`, not `"code-check"`.                                                   |
| `FAIL  rent failures, which have one right answer, go to a code check` (count-the-failures)                               | A mode about rent has a decision other than `code check`.                                                               | A rent value has one right answer in the lease, so compare it in code. Do not pay a judge to read it. For example, `amended-rent-missed` gets `"decision": "code check"`.              |
| `FAIL  marks.csv exists with the columns trace_id and mark` (mark-the-traces)                                             | `marks.csv` is missing, or its first line is not `trace_id,mark`.                                                       | Start the review app with `uv run review mark-the-traces`; it writes the file for you. Or keep the header line `trace_id,mark` at the top.                                             |
| `FAIL  every trace in sample.jsonl has one mark, and no other trace has one` (mark-the-traces)                            | Some traces have no mark, some have two, or a mark names a trace that is not in your sample.                            | Go through all 40 traces in the review app. Each trace gets exactly one row, for example `abs-0024,fail`.                                                                              |
| `FAIL  every mark is pass or fail, with no defer left` (mark-the-traces)                                                  | You put some traces aside with "defer" and did not come back to them.                                                   | Come back to the deferred traces and decide pass or fail on each one.                                                                                                                  |
| `FAIL  every trace with a planted fault is marked fail` (mark-the-traces)                                                 | You marked pass on a trace that has a known mistake in it.                                                              | Compare rent, rent steps and renewal notice days with the lease text, amendments included. For example, lease L008 says $2,125.00 in c04, but Amendment No. 1 changes it to $2,275.00. |
| `FAIL  your marks agree with Dana's on at least 32 of the 40 traces` (mark-the-traces)                                    | Your marks differ from Dana's on more than 8 traces.                                                                    | A trace fails when any field differs from the signed lease, not only rent. For example, trace `abs-0018` has the wrong rent, and it also leaves out the trash the landlord pays for.   |
| `FAIL  report.txt exists in this folder` (meet-fernhill)                                                                  | There is no `report.txt` in `00-orientation/01-meet-fernhill/problem/`.                                                 | From the repo root, run `uv run fernhill report --out 00-orientation/01-meet-fernhill/problem/report.txt`.                                                                             |
| `FAIL  it is the report for the live release` (meet-fernhill)                                                             | The first line of `report.txt` is not the report title.                                                                 | Write the file with `uv run fernhill report`, not by hand. Then its first line is `Fernhill eval report, release: live`.                                                               |
| `FAIL  it has all five report lines` (meet-fernhill)                                                                      | One of the five lines is missing, often because the report stopped on an error.                                         | Run the whole report again. If a line is missing, read the error above it and look it up on this page.                                                                                 |
| `FAIL  the gate blocks the cheaper model` (meet-fernhill)                                                                 | The gate line does not say `BLOCKED`.                                                                                   | Run `uv run world reset`, then write the report again on the default replay provider. The line should end `BLOCKED: rent newly wrong on 9 amended leases (critical)`.                  |
| `FAIL  its world line matches the world in this repo` (meet-fernhill)                                                     | The report came from another copy of the world.                                                                         | Run `uv run world reset` and write the report again. Its last line should be `World: 1,840 units, 120 leases in the eval corpus, fingerprint d6ac97fbb4a7`.                            |
| `FAIL  failure_modes.yaml lists 4 to 8 modes` (name-the-failure-modes)                                                    | You have fewer than 4 modes, or more than 8.                                                                            | Group your notes. Merge modes that share a cause in the data. Split a mode that hides two different behaviours.                                                                        |
| `FAIL  every mode has a name in lower-case-with-dashes, a definition and at least one example` (name-the-failure-modes)   | A mode is missing a part, or its name has capitals or spaces.                                                           | Copy the block shape from the comment at the top of `failure_modes.yaml`. For example, `name: amended-rent-missed` with a `definition:` and `examples: [abs-0026]`.                    |
| `FAIL  no mode has a generic name like hallucination, formatting or other` (name-the-failure-modes)                       | A mode name says that something went wrong, but not what.                                                               | Name what happened to which field. For example, `amended-rent-missed`, not `hallucination`.                                                                                            |
| `FAIL  every definition is one sentence of 25 words or fewer` (name-the-failure-modes)                                    | A definition is too long, or it has more than one sentence.                                                             | Write one short sentence a colleague can apply to a new trace. For example: "The abstract keeps the rent from the original lease and ignores a later amendment."                       |
| `FAIL  every example is a trace you marked fail and wrote a note on` (name-the-failure-modes)                             | An example names a trace you marked pass, or a trace with no note.                                                      | Use trace ids from `notes.csv` as examples. For example, `abs-0026` is in the sample solution's `notes.csv`.                                                                           |
| `FAIL  labels.csv has a column per mode and a row per reviewed trace, with 0 or 1 in every cell` (name-the-failure-modes) | `labels.csv` is missing a column or a row, or a cell holds something other than 0 or 1.                                 | Give every trace in `marks.csv` one row, and put 0 or 1 under every mode. For example, `abs-0026,1,0,0,0,0,0`.                                                                         |
| `FAIL  every failed trace has at least one mode, and every passed trace has none` (name-the-failure-modes)                | A failed trace has only 0s, or a passed trace has a 1.                                                                  | A failed trace with no mode means a mode is missing. Add a mode, or widen a definition so it covers that trace.                                                                        |
| `FAIL  the examples of each mode carry a 1 in that mode's column` (name-the-failure-modes)                                | A trace you named as an example has a 0 under its own mode.                                                             | Put a 1 in `labels.csv` for each example you named in `failure_modes.yaml`. For example, if `abs-0026` is an example of `amended-rent-missed`, its row has 1 there.                    |
| `FAIL  one mode covers every amendment failure in the sample` (name-the-failure-modes)                                    | The traces where rent misses Amendment No. 1 are split across several modes.                                            | These traces are one behaviour, so give them one mode, such as `amended-rent-missed`.                                                                                                  |
| `FAIL  notes.csv exists with the columns trace_id and note` (note-the-failures)                                           | `notes.csv` is missing, or its first line is not `trace_id,note`.                                                       | Keep the header line `trace_id,note` and add one row for each failed trace.                                                                                                            |
| `FAIL  every trace marked fail has a note` (note-the-failures)                                                            | A trace you marked fail has an empty note.                                                                              | Open `uv run review note-the-failures`. It shows only the failed traces and saves each note for you.                                                                                   |
| `FAIL  every note has at least 5 words` (note-the-failures)                                                               | A note is too short to tell anyone what went wrong. For example, `wrong field`.                                         | Say which field is wrong, what the abstract says and what the lease says. For example: "Renewal notice days read 60, but the renewal clause says not less than 90 days."               |
| `FAIL  no note names a fix or a cause` (note-the-failures)                                                                | A note guesses why it went wrong, or how to fix it. For example, "The prompt should tell the model to read amendments." | Describe what you see; do not diagnose. Drop words like should, prompt and fix.                                                                                                        |
| `FAIL  each note on a planted fault names the field that went wrong` (note-the-failures)                                  | A note on a known mistake does not say which field is wrong.                                                            | Name the field in the note: rent, the rent step, or the renewal notice days.                                                                                                           |
| `FAIL  sample.py exists` (sample-the-traces)                                                                              | There is no `sample.py` in the step's `problem/` folder.                                                                | Keep `sample.py` in this problem folder and edit it there.                                                                                                                             |
| `FAIL  sample.py --seed 7 runs and writes 40 traces` (sample-the-traces)                                                  | Your script stopped on an error, or it wrote a number of traces other than 40.                                          | Run `uv run python sample.py --seed 7` and read the error. `sample()` must return a list of 40 traces.                                                                                 |
| `FAIL  every trace id is real and none repeats` (sample-the-traces)                                                       | A trace id is not in the trace file, or the same trace is in the sample twice.                                          | Write whole trace lines from `world/data/traces/abstractor.jsonl`, and never pick the same trace twice.                                                                                |
| `FAIL  at least 8 traces of amended leases` (sample-the-traces)                                                           | Your sample has fewer than 8 traces of leases with an amendment.                                                        | Pick traces where `amendments` is above 0 first, then fill the rest. For example, trace `abs-0018` (lease L008) has `"amendments": 1`.                                                 |
| `FAIL  at least 3 traces of commercial leases` (sample-the-traces)                                                        | Your sample has fewer than 3 traces of shop leases.                                                                     | Add a group for `lease_type` commercial and draw from it. A plain random draw often misses the 10 shop leases.                                                                         |
| `FAIL  the same seed gives the same sample` (sample-the-traces)                                                           | Two runs with `--seed 7` gave different samples.                                                                        | Make one `random.Random(seed)` and draw every pick from it. Then sort the result by `trace_id`.                                                                                        |
| `FAIL  a different seed gives a different sample` (sample-the-traces)                                                     | `--seed 7` and `--seed 8` gave the same sample.                                                                         | Draw with the seed you are given. A fixed list of ids is not a sample.                                                                                                                 |
